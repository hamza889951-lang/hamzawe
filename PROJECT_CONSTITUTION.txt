# دستور المشروع — الإصدار 3.2 (v1.0 مستقر)


---


## 1. نظرة عامة


**نظام حجز مواعيد طبية** عبر واتساب لعيادة واحدة (v1.0)، مبني على **Google Apps Script** وفق بنية معمارية طبقية صارمة (CAS).


**النواة المعمارية مستقرة ومكتملة.** جميع الخدمات الأساسية + المولد + المجدول + المراقبة + Idempotency تعمل داخل النواة. أي تطوير لاحق يُعد إضافة ميزات جديدة أو تحسينات أداء.


---


### 1.1 الأدوار


| الدور | المسؤول | المسؤولية |
|-------|---------|------------|
| المشرف المعماري | جي (G) | القرارات المعمارية، مراجعة الأخطاء، صياغة ADR |
| المبرمج المنفذ | كلود (Claude) | التنفيذ ضمن القرارات المعمارية |

## 5. المكونات الجديدة (ADR-022, ADR-023, ADR-024)


### 5.1 AvailabilityHorizonMaintainer.gs — Application Service


**المسؤولية:** ضمان وجود أفق زمني لا يقل عن 30 يوماً من الفتحات المتاحة.


**التفاصيل:**
- يُستدعى من `Scheduler.main()` بعد `MaintenanceService.run()`.
- يستخدم `SlotGenerator` (Domain Helper) لحساب الأيام المفقودة وتوليد الفتحات الجديدة.
- يكتب عبر `SlotRepository.insertBatch` دفعة واحدة (تحسين أداء).
- سياسة الفشل: Best Effort (ADR-017) — يُسجَّل الفشل ولا يُوقف التشغيل.


**الاعتماديات:**
- `SlotGenerator.calculateGenerationPlan(latestSortKey, settings)`
- `SlotGenerator.calculateDailySlots(date, settings, slotDuration)`
- `SlotGenerator.isWorkingDay(date, settings)`
- `SlotRepository.insertBatch(slots)`


---


### 5.2 ProcessedMessagesService.gs — Idempotency (ADR-023)


**المسؤولية:** منع تكرار معالجة نفس الرسالة من Webhook.


**التفاصيل:**
- يستخدم `PropertiesService` لتخزين بصمة الرسالة مع الطابع الزمني.
- نافذة 5 دقائق (قابلة للتكوين عبر `DUPLICATE_WINDOW_MS`).
- عند وجود `messageId` من UltraMsg، يُستخدم مباشرة.
- عند غيابه، يُبنى بصمة من `phone + message + الدقيقة` (دقة دقيقة) لتجنب رفض الرسائل المتطابقة في أوقات مختلفة.


**واجهة الاستخدام:**
```gs
ProcessedMessagesService.isDuplicate(messageId, phone, message) → boolean
ProcessedMessagesService.markProcessed(messageId, phone, message)
```


---


### 5.3 HealthCheckService.gs — مراقبة تلقائية


**المسؤولية:** فحص صحة النظام بشكل دوري وإرسال تنبيهات للمشرف.


**التفاصيل:**
- يُستدعى من `Scheduler.main()` كخطوة رابعة.
- يفحص:
  - وجود بيانات في `Availability`
  - وجود بيانات في `SYSTEM_LOG`
  - صحة `Settings`
- يُسجّل النتائج في `SYSTEM_LOG`.
- إذا وُجدت مشاكل، يُرسل رسالة واتساب إلى `ADMIN_PHONE` (من Script Properties).


**سياسة الفشل:** Best Effort — فشل HealthCheck لا يوقف Scheduler.


---


### 5.4 Backup (ADR-024) — موثق في الدستور


**السياسة:**
- نسخ احتياطي أسبوعي للـ Sheets (Availability, Conversations, Settings, SYSTEM_LOG).
- يُحتفظ بآخر 4 نسخ (شهر كامل).
- يُنفَّذ عبر سكريبت منفصل (يُضاف مستقبلاً أو يُنفَّذ يدوياً).

## 7. تدفق Webhook النهائي (مع ADR-023)


```
doPost(e)
  ├─ WhatsAppAdapter.parseIncomingPayload(e)
  │   └─ تعيد { phone, message, messageId } أو null
  ├─ null? → تسجيل WEBHOOK_PARSE_FAILED → IGNORED
  ├─ ProcessedMessagesService.isDuplicate(msgId, phone, message)?
  │   └─ true → OK (بدون معالجة) ⭐ Idempotency
  ├─ ProcessedMessagesService.markProcessed(msgId, phone, message) ⭐
  ├─ Router.dispatch({ phone, message })
  │   └─ تعيد Result { reply, conversationState }
  ├─ WhatsAppAdapter.sendMessage(phone, reply)
  │   └─ فشل؟ → تسجيل WEBHOOK_SEND_FAILED
  └─ Exception? → WEBHOOK_CRASH → ERROR_LOGGED
```

## 8. تدفق Scheduler النهائي


```
Scheduler.main()
  ├─ 1. MaintenanceService.run()
  │   ├─ runCleanup() → RESERVED منتهية → FREE (Batch)
  │   └─ runExpiration() → FREE منتهية → EXPIRED (Batch)
  │
  ├─ 2. AvailabilityHorizonMaintainer.ensureHorizon()
  │   ├─ SlotGenerator.calculateGenerationPlan()
  │   ├─ إن كان بحاجة توليد ← SlotGenerator.calculateDailySlots() لكل يوم
  │   └─ SlotRepository.insertBatch() دفعة واحدة
  │
  ├─ 3. ReminderService.processPendingReminders(sendFn)
  │   ├─ collectPendingReminders()
  │   ├─ لكل مهمة: sendFn(phone, message)
  │   └─ لكل نجاح: markReminderSent(slotId)
  │
  ├─ 4. HealthCheckService.run() ⭐ (مع try/catch خاص)
  │   ├─ فحص Availability, SYSTEM_LOG, Settings
  │   ├─ تسجيل النتيجة في SYSTEM_LOG
  │   └─ إن كانت مشاكل ← إرسال واتساب للمشرف
  │
  └─ تسجيل SCHEDULER_RUN شامل
```

## 9. قواعد تشغيلية وإرشادية


### 9.1 قبل الإطلاق (Go-Live Checklist)


- [ ] التأكد من وجود جميع الأوراق في Spreadsheet: `Availability`, `Conversations`, `Settings`, `SYSTEM_LOG`.
- [ ] التأكد من وجود جميع Script Properties:
  - `SPREADSHEET_ID`
  - `ULTRAMSG_INSTANCE_ID`
  - `ULTRAMSG_TOKEN`
  - `ADMIN_PHONE`
- [ ] تشغيل `RUN_healthCheck()` والتأكد من ظهور `✅ SYSTEM READY`.
- [ ] تشغيل `RUN_previewHorizon()` ومعاينة خطة التوليد.
- [ ] تشغيل `RUN_ensureHorizon()` وتأكيد كتابة الفتحات.
- [ ] تشغيل `RUN_scheduler()` وتأكيد اكتمال جميع الخطوات دون أخطاء.
- [ ] اختبار Webhook يدوياً عبر `RUN_testWebhook()` (محاكاة doPost).
- [ ] إيقاف أي سيناريوهات Make.com تعمل على نفس Sheets.
- [ ] النسخ الاحتياطي اليدوي الأول لجميع الأوراق.


### 9.2 أثناء التشغيل (Daily/Weekly)


- **يومياً:** مراقبة سجلات `SCHEDULER_RUN` و `HEALTH_CHECK` في `SYSTEM_LOG`.
- **أسبوعياً:** التحقق من عدم تجاوز `PropertiesService` حد 500 مفتاح (Idempotency).
- **شهرياً:** مراجعة أداء `updateRowByColumn` واتخاذ قرار بتحسينه إذا لزم الأمر.


### 9.3 سياسة الفشل (Failure Policy)


| المكون | سياسة الفشل | التوثيق |
|--------|-------------|---------|
| Webhook (Idempotency) | Best Effort — فشل التخزين لا يمنع المعالجة | ADR-023 |
| Scheduler | Best Effort — أي خطأ يُسجَّل ولا يُعاد رميه | ADR-020 |
| Maintenance | Best Effort — فشل تحديثات Batch يُسجَّل فقط | ADR-017 |
| Reminders | Best Effort — فشل تذكير لا يوقف الباقي | ADR-017 |
| HealthCheck | Best Effort — فشله لا يوقف Scheduler | — |
| AvailabilityHorizon | Best Effort — فشل التوليد لا يوقف Scheduler | ADR-022 |

## 13. شهادة جاهزية الإطلاق (Beta Readiness Certificate)

- النواة مستقرة وخالية من الأخطاء القاتلة.
- أداء الصيانة محسّن (Batch Updates).

- Idempotency تحمي من تكرار الرسائل.
- المراقبة التلقائية (HealthCheck) تعمل.
- النسخ الاحتياطي موثق.
- جميع العقود (CAS) والمقررات (ADR) موثقة في هذا الدستور.
